- 增加安装、登记、更新及回滚文档、标准库测试和 GitHub Actions 三系统矩阵。SemVer 从 V3 的 `3.0.0` 开始。

## C · 自助安装机制

用户明确授权后，AI 在独立目录克隆 GitHub，审查脚本和发行 commit，执行 `doctor`、dry-run、`--apply`，再验证 `status` 和登记工作区。每一端都有原生入口，最后指向单一版本正文。更新采用独立、干净且固定 commit 的候选 checkout，回滚使用已保留的候选。详见 [安装手册](../INSTALL.md)。

## E · 质量测试

测试入口为 `python3 -B scripts/validate.py` 与 `python3 -B -m unittest discover -s tests -v`。静态检查包括编译语法、公开路径/敏感格式、Markdown 相对链接、完整性及版本一致。本机静态验证通过并覆盖 37 个发行文件，17 项标准库测试全部通过。测试使用真实 Git 与合成用户目录。独立评审另验证同名项目不激活和跨域会话的增量规则。

## F · 安全审计

- 预演不写入，写入仅落在受管用户目录和精确平台入口。常规安装不修改全局规则、权限、Hook 和项目配置。迁移只处理回执、模板、边界标记和原始前缀均匹配的 V2 文件。
- 安装器比较固定 commit 的 HEAD、索引和工作树，读取 Git 对象与发行白名单。检查不运行候选脚本或 Git clean filter。来源 URL 和 commit 是标识，不替代对实际内容或发行签名的审查。
- 新文件采用原子无覆盖提交，POSIX 写入使用目录描述符及文件身份校验；Windows 拒绝预检发现的重解析点，对打开的文件检查身份。Windows 的内建路径 API 仍要求在受信且没有外部进程并发换目录的本机用户目录执行。用户级回执和缓存是本机信任范围内的文件，不是对同账号恶意修改的防护边界。
- 失败可按日志恢复。安装器内部锁序列化写入；发生第三方编辑且归属无法确定时保留现场。进程中断测试覆盖可恢复状态，未验证断电、网络文件系统或其他客户端同时重命名目录的极端条件。
- V2 基线曾包含本机路径，新树已移除。未发现符合扫描样式且经确认的真实凭证。历史不改写，保持原始 commit。报告只记录脱敏证据，原始工作树快照和真实用户配置留在本机。

## G · 零侵入
