# V3.1 Multica 集成报告

## 基线与官方证据

以远程 `feat/v3-portable-agent-skill` 的 `1454fe5c8f02235096ec04a5a060c9f8c0eafaff` 和保留其历史的本机 RC `ea51c55b862eb8b23e37eb8c2374e65585ba5425` 为起点。远程 `main` 查询结果为 `920411cf5c20192b0bf845cdc449af5aae9fbb3e`。开始时本地功能分支干净，独立 V3.1 分支远端尚未创建。

核对 Multica 当前官方源码、文档和本机内置 CLI。机制和来源见 [兼容证据](../integrations/multica/compatibility.md)。工作区 Skills、绑定、运行时交付与模型执行分别取证。原生机制覆盖导入、刷新、绑定和执行，本仓库只提供可复核的内容包和离线预演。

## 变更

- `manifest.json`、`CHANGELOG.md` 升为 3.1.0。HikariCP 路由补充数据库结构规则。既有正文、指纹与四端生命周期保留。
- `integrations/multica/` 提供通用与三种角色 Instructions、Squad 交接、安装/更新/解绑、真实平台兼容和日志验收。
- `scripts/multica.py` 从经审查的固定提交构建原生 `.skill`，检查限额、敏感样式、安全路径与完整性。只读比对 Workspace/Runtime 同名内容与版本，预演原生追加绑定或单项解绑。
- `scripts/validate.py` 及 `tests/` 接入原有 GitHub Actions 静态和跨系统单测，无新依赖或外部服务凭证。
- `README.md`、`INSTALL.md` 更新 V3.1 来源和一键配置提示词。

## 权限与规范继承

每位指定 Agent 分别核验绑定、交付、可信 Git 根、规则来源与自身读取证据。Squad 的流程角色不授予权限。依赖变更和无法解决的实质冲突仍由用户裁决，Trellis/Cairn 继续适用。验证仅允许独立工作树或隔离目录；Multica daemon 可能在执行根写入原生工具配置，禁止用 HiMate 原始工作树验证。导入前审查 Workspace 共享范围，规范仍含工程结构与契约背景。
