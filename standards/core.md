# 核心约束

- CORE-01 MUST。以本轮用户授权和文件范围为实施边界，先读现行入口、契约、构建清单和同层样例。优先用最小、可验证的改动，保留兼容分支、空态、异常、权限和历史数据语义。范围外及受保护模块按当前项目约定处理。
- CORE-02 MUST。遵循平台权限与用户授权。规范的维护和测试在独立 Skill 副本或测试沙箱内进行，安装仅写本 Skill 的用户级状态与授权入口。仓库及其 AI 工具目录在该类任务中严格只读。正常业务开发的写权限由当轮用户请求决定。
- CORE-03 MUST。依赖变更必须先获得授权，按 [依赖审批](dependency-policy.md) 执行。
- CORE-04 MUST。保护凭证、Token、Cookie、生产配置、个人信息及用户消息。只采集最少必要证据，日志和报告保留名称、来源及脱敏上下文。接触真实环境前确认范围和授权。
- CORE-05 SHOULD。先核对项目 README 的现行事实源。保持中文沟通与项目术语。配合 Trellis 实施与验证，Cairn 负责现有项目知识。规范安装期间仅只读引用它们。
- CORE-06 SHOULD。以受影响模块的现有脚本做最小验证，区分既有失败、本轮回归和未验证。当前外部规范验证只运行自身脚本，业务构建及生产数据操作由其各自授权决定。
