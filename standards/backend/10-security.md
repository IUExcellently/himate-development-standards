# 后端安全

适用公开、内部、管理端入口以及 SQL、文件、回调、鉴权和服务间调用。以现行 Gateway/服务机制及已使用 Spring Security 的模块为准，见 [E09](../../references/coding-evidence.md)。

- SEC-01 MUST。认证与授权分别检查，在服务边界核验主体、角色、对象所有权、租户和操作权限。防水平/垂直越权及 IDOR；前端隐藏按钮、请求传入 userId 或可伪造头部不构成授权。内部调用核对可信来源与服务鉴权，保留 Gateway / admin / user 入口差异。
- SEC-02 MUST。输入类型、长度和业务允许值在信任边界校验。SQL 绑定见 [SQL](05-sql-guidelines.md)。服务器外联目的地限制 scheme、主机和端口，对解析、代理、重定向及私网访问作既有安全控制。反序列化选择明确 DTO 与安全配置，保留必要拒绝策略。
- SEC-03 MUST。文件下载和回调校验身份、访问范围与路径归属。按实际文件系统核对规范化后的真实根目录、符号链接策略和访问权限，上传验证大小、内容和安全名称；执行与后续消费隔离。数据库/缓存等账号按最小权限配置。
- SEC-04 MUST。访问 Token/Cookie、密钥、PII、用户消息、设备和生产参数按既有策略保护，结构化日志脱敏。错误响应保留协议必要字段并隐藏内部细节。核对 Cookie 属性、CORS、CSRF 与实际凭证传输方式。
- SEC-05 SHOULD。为匿名、权限不足、跨租户、错误对象、服务凭证失效及过量输入添加受影响范围的回归验证。按当前系统授权执行测试。避免把现有未经核实的安全缺口固定成规范。
